# Fish-under-sea GitHub 主页融合设计

日期：2026-10-10

## 目标与依据

在已有个人主页仓库中融合用户指定的两组截图：上半部分采用 [innng](https://github.com/innng/innng) 的打字标题、浅灰等宽简介区、小狐狸 GIF 和徽章排列；下半部分采用 [elysia395](https://github.com/elysia395) 的贡献贪吃蛇与双栏统计。

身份统一为「个人开发者」。中英文主页均移除学校、年级、班级和学生身份。图片使用用户提供的原始素材，原始文件不修改。使用 GitHub 支持的 Markdown、HTML 和 SVG 图片，不增加独立网站或运行时 JavaScript。

## 页面顺序

1. 居中的打字标题与右侧人物图片。
2. 居中的浅灰等宽简介区。
3. 居中的原案例小狐狸 GIF，以及下方的徽章链接。
4. 简短介绍与真实代表项目链接。
5. 全宽贡献贪吃蛇动画。
6. 等宽双栏统计：左侧个人活动和仓库概况；右侧语言分布与立体贡献日历。
7. 折叠的技术栈及完整项目索引，以及联系方式和中英文切换入口。

不加入博客、最近发布自动摘要、额外宠物或装饰动图。原有 Banner 文件保留，但不继续作为顶部展示。

## 必须保留的参考区块

### 打字标题

保留原案例的居中、等宽字体、两行标题和逐字出现效果，使用 `readme-typing-svg`，不换成普通静态标题。保留 `Inconsolata` 字体、浅金橄榄色视觉方向、约 4 秒的打字节奏。根据明暗主题调整颜色，保证文字可读。

默认标题内容：

```text
Hello hello
I'm Fish-under-sea, a personal developer
```

第一行保留案例的问候，第二行改成用户自己的账号和个人开发者身份。不沿用原作者姓名或虚构个人经历。页面另外保留可读的账号文本，标题图片不可用时仍能识别作者。

### 简介区

沿用原案例的 `<pre>` 结构、居中等宽排版与 GitHub 提供的浅灰底。深色主题使用 GitHub 自身的代码块背景。不另外模拟卡片或添加自定义 CSS。

默认中文内容：

```text
个人开发者 · AI Agent · 桌面工具
Python · TypeScript · JavaScript
DSH 插件 · 自动化 · 开源项目
把想法做成真正能用的工具
```

英文主页表达相同内容，不混入学校或学生信息。只保留已有主页中能核实的开发方向和语言。为移动端缩短每行文本，不靠大量空格实现对齐。

### 小狐狸 GIF 与徽章

保留原案例的 GIF 本体、居中位置与约 40 像素展示高度，不改成静态图片、图标或另一个角色。原始来源：

<https://raw.githubusercontent.com/innng/innng/master/assets/kyubey.gif>

以原始 URL 引用，并记录来源及上游未声明的素材授权，不将第三方角色素材声明为本仓库 MIT 授权作品。实现时核实文件确实包含多帧动画，并保留原来的动作。

动图下方保留两个紧凑徽章的位置与间距。链接改成用户自己的 GitHub 仓库列表和已有公开邮箱，不照搬原作者的 `osu!` 或 `enka.network` 账号。

## 人物图片与介绍

用户素材真实格式为 JPEG，尺寸为 3840 × 2400。实现时复制成格式正确的仓库内 JPEG，保留原图不变；展示宽度约占顶部的 30%，保持 8:5 比例，不裁成案例中的竖图、不添加文字覆盖。

人物图与左侧参考区块共存，但不能挤压标题和简介。窄屏优先保证文字可读，图片允许与文本自然换行。不依赖 GitHub 会过滤的脚本或 CSS。

简短介绍默认使用：

> 个人开发者，专注 AI Agent、桌面工具与 DSH 插件。把「AI 能替我做什么」变成「我已经做出来了什么」。

代表项目链接使用 DSH 插件生态、WinTunerPro 和 MnemoTranscode 的现有真实仓库。保留其他项目索引与联系方式，不编造作者身份、项目数据或经历。

## 动态统计与权限

贡献贪吃蛇使用 `Platane/snk`，提供明暗两套 SVG。双栏统计使用 `lowlighter/metrics`：左栏配置 `header, activity, community, repositories, metadata`，右栏开启 `isocalendar` 和 `languages`。所有账号参数均使用 `Fish-under-sea`，时区为 `Asia/Shanghai`。

由 GitHub Actions 定期及手动生成，产物存入独立 `output` 分支，不把定期更新提交写进主页源码。生成任务串行处理输出写入，避免两个任务同时更新同一分支造成冲突。

贪吃蛇使用 GitHub 提供的 `GITHUB_TOKEN`。统计需要的个人访问令牌（Personal Access Token）仅通过仓库 Secret `METRICS_TOKEN` 配置，写入产物使用 `GITHUB_TOKEN`。不得要求用户在聊天中粘贴令牌，不得写进文档、源码、图片或 Git 历史。默认只展示公开资料，不申请私有仓库访问权限。

缺少统计 Secret 时明确提示配置需求，不声称双栏统计已经生成；保留现有有效产物，不用空文件覆盖。第一次还没有产物时提供明确的生成入口，不借用别人的统计图。刷新失败时保留上次数据并展示真实更新时间，不声称数据实时有效。

访问计数不是用户强调的核心效果，首版不加入第三方计数器，避免把图片请求量误称为真实独立访客数。

## 动画与可访问性

用户明确要求保留打字标题、小狐狸 GIF 和贡献贪吃蛇。普通动效模式下必须实际呈现三种动画，不把静态预览宣称为完成。

通过 `<picture>` 为偏好减少动态效果的用户提供静态终态；普通模式继续使用原动画。图片和统计图添加有效的 `alt` 与尺寸约束。标题服务不可用时，账号和简介仍可读；统计图不可用时，代表项目和联系方式仍可访问。

## 变更边界

预计修改两份现有中英文主页文档，新增用户人物图、必要的静态动效回退素材、素材来源记录和两类 Actions 工作流。保留原有许可文件及其他用户文件。不增加框架、产品依赖或独立服务。

设计确认后才开始主页实现。先在本地检查和预览，推送远程及触发线上工作流需要用户明确确认。尚未验证的线上动画、统计图和明暗主题不得报告为已通过。

## 验收

- 顶部具备指定案例的打字标题、浅灰等宽简介区、同一小狐狸 GIF 和紧凑徽章布局。
- 使用 `Fish-under-sea` 和「个人开发者」，中英文均无学生身份；不沿用别人的姓名或账号链接。
- 用户人物图保留主体与原比例，原始文件没有修改。
- 普通模式下标题逐字出现、小狐狸确实运动、贪吃蛇播放；减少动态效果模式下内容保持可见。
- 下方贡献动画及双栏统计使用用户自己的真实数据，公开资料与私有数据边界明确。
- 代表项目、完整项目索引、联系方式及中英文入口有效。
- 在桌面、375 像素窄屏以及 GitHub 明暗主题检查图片、文字与统计图，无遮挡或页面级横向溢出。
- 本地检查、真实浏览器预览与线上工作流验证分别报告，不把未运行的项目列为通过。
